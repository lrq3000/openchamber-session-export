## Observed causes and existing capabilities

`SessionSource` currently retains all messages/events and enforces a shared 128 MiB limit plus 64 MiB response/log limits. `MarkdownRenderer.render` and archive `JSON.stringify`/array joins then build whole-session strings. Removing only the first guard would risk heap exhaustion elsewhere. The panel also stops polling at fifteen minutes. The established `yazl` dependency already supports streaming ZIP and automatic ZIP64; reuse it. Add the established `stream-json` parser, pinned after checking its package/API, instead of writing a JSON parser. Use its unpacked string/number tokens so a large individual value does not need one giant JavaScript string.

Static source inspection of installed OpenChamber 2.6.1 established that native `Export Markdown` is separate from guest actions, keyed independently as `guest.id:action.id`; `export-session` does not collide with it. The sidebar inserts guest actions after native export; desktop header menus interpose `Open in Mini Chat`, and the manifest has no supported priority/placement field. Native disappearance reported by the user is not yet reproduced. Verify coexistence in the actual UI; do not claim a masking bug fixed if absent, rename the action on an unsupported theory, patch installed host assets, or imitate/replace the native exporter.

The sandbox SDK exposes neither a generic ZIP Save As command nor trustworthy desktop/local-client identity. The host's private `desktop_save_markdown_file` command writes Markdown text itself and cannot be reused for ZIP. The user accepted an extension-only solution, normal host menu ordering and manual-path fallback when the client context is uncertain. The existing Windows host service may display `System.Windows.Forms.SaveFileDialog` through a fixed PowerShell executable in STA mode; actual runtime operation still requires validation.

## Destination workflow

Desktop local export requests a destination for every actual ZIP creation, before writing the archive. The Windows dialog must run as an acknowledged asynchronous job because both SDK and host service proxy have ordinary 20-second request deadlines. Use `shell:false`, a fixed trusted executable, `-NoProfile` and `-STA`; pass paths/titles as data, not executable interpolation. Prevent duplicate dialogs, freeze the session/destination for an action, validate an absolute local ZIP path, and preserve existing-file protection. Closing/cancelling the dialog means no export and no silent write to the old path.

Do not infer the client from the service's `process.platform` or Electron runtime. Use a deliberately conservative client-capability decision for the ordinary local desktop and validate it in the installed app. If identification is ambiguous, the dialog fails/is unavailable, or a browser is in use, leave the existing output-directory field available. Browser paths continue to refer to the service host, not the browser device; never automatically open a dialog on a remote server. Any heuristic must be disclosed as such, not presented as an SDK guarantee. A user cancellation is not an unavailable-dialog fallback.
